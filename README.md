# XAUUSD Footprint Binary Option Indicator

## เป้าหมายของโปรเจกต์

สร้างอินดิเคเตอร์สำหรับ XAUUSD ที่ใช้ข้อมูล tick และ Footprint เพื่อทำนายว่า **แท่งเทียน 5 นาทีถัดไปจะขึ้นหรือลง** สำหรับการเทรด Binary Option โดยมีเวลาหมดอายุ 1 แท่ง หรือ 5 นาที

อินดิเคเตอร์ไม่ได้พยายามทำนายว่าราคาจะวิ่งไปกี่จุด เป้าหมายหลักมีเพียง:

- `UP`: ราคาปิดของแท่งถัดไปสูงกว่าราคาปิดของแท่งปัจจุบัน
- `DOWN`: ราคาปิดของแท่งถัดไปต่ำกว่าหรือเท่ากับราคาปิดของแท่งปัจจุบัน
- `NO SIGNAL`: โมเดลยังไม่มั่นใจพอ ไม่ควรเปิดออเดอร์

### โครงสร้างไฟล์สำคัญ

## ลำดับการทำงาน

1. โหลด tick data จากไฟล์ CSV
2. รวม tick เป็นแท่งเวลา 5 นาที
3. สร้าง Footprint จาก buy/sell volume หรือ tick count fallback
4. สร้าง feature จาก Delta, Volume, POC, Imbalance และ Stacked Imbalance
5. เพิ่ม context จากแท่งก่อนหน้าและ rolling window
6. ให้โมเดลทำนายความน่าจะเป็นที่แท่งถัดไปจะขึ้น
7. แปลง probability เป็นสัญญาณ UP, DOWN หรือ NO SIGNAL
8. เมื่อแท่งถัดไปปิด ให้บันทึกว่าทายถูกหรือผิด

## กติกาสัญญาณ

ค่าเริ่มต้นใช้ probability threshold `0.55`:

```text
probability >= 0.55       -> UP
probability <= 0.45       -> DOWN
0.45 < probability < 0.55 -> NO SIGNAL
```

การมี `NO SIGNAL` เป็นเรื่องสำคัญ เพราะไม่ควรบังคับโมเดลให้ทายทุกแท่ง หากความมั่นใจต่ำ

## ความหมายของการทายถูก

การทาย 1 ครั้งเริ่มเมื่อแท่งปัจจุบันปิด และหมดอายุเมื่อแท่ง 5 นาทีถัดไปปิด

```text
ถ้า next_close > current_close และโมเดลทาย UP   -> ถูก
ถ้า next_close <= current_close และโมเดลทาย DOWN -> ถูก
```

ดังนั้นเกณฑ์นี้วัดผลให้ตรงกับราคาเข้าและราคาหมดอายุของ Binary Option ไม่ใช่การดูว่าแท่งถัดไปมี `close > open` หรือไม่

### Pattern filter

อินดิเคเตอร์มีตัวกรองยืนยันด้วย Candle Body เป็นค่าเริ่มต้น:

- สัญญาณ `UP` ต้องมี body ของแท่งปัจจุบันเป็นบวก
- สัญญาณ `DOWN` ต้องมี body ของแท่งปัจจุบันเป็นลบ
- ถ้า body เป็นศูนย์หรือสวนทางกับสัญญาณ จะไม่เปิดออเดอร์

ตัวกรองนี้ใช้เฉพาะข้อมูลของแท่งปัจจุบันที่ปิดแล้ว จึงไม่ใช้ข้อมูลอนาคต

ไม่ควรดูเฉพาะ Accuracy เพราะโมเดลอาจเลือกทายเฉพาะบางช่วง และไม่ทายช่วงที่ไม่มั่นใจ

## การจำลองทุน Binary Option

ค่าตัวอย่างสำหรับทดสอบ:

```text
ทุนเริ่มต้น: 2,000 บาท
เงินเดิมพันพื้นฐาน: 100 บาท
Payout: 80%
ชนะ: ได้กำไรสุทธิ 80 บาท
แพ้: เสียเงินเดิมพัน 100 บาท
```

จุดคุ้มทุนของ payout 80% คือประมาณ `55.56%`:

```text
1 / (1 + 0.80) = 55.56%
```

ต้องทดสอบว่า Accuracy สูงกว่าจุดคุ้มทุนนี้อย่างสม่ำเสมอในข้อมูลหลายช่วงเวลา ไม่ใช่เฉพาะเดือนเดียว

### Money management ที่ใช้เปรียบเทียบเป็นค่าเริ่มต้น

ปัจจุบันใช้ `fixed_stake` เป็นโหมดหลัก โดยเดิมพันคงที่ `100 บาท` ทุกสัญญาณ และรัน `martingale` แยกอีกชุดเพื่อเปรียบเทียบ

เหตุผลคือการทดลองกับชุด out-of-sample เดียวกันให้ผลโดยประมาณ:

| วิธี | ผลกำไร/ขาดทุน | Maximum drawdown |
| --- | ---: | ---: |
| Fixed 100 บาท | -280 บาท | -1,900 บาท |
| Fixed fractional 1% | -70.02 บาท | -414.52 บาท |
| Martingale สูงสุด 400 บาท | -1,660 บาท | -5,280 บาท |

ผลนี้ไม่ได้แปลว่า fixed fractional หรือ fixed stake ทำให้โมเดลกำไร แต่แสดงให้เห็นความแตกต่างของความเสี่ยงเมื่อ win rate ยังไม่สูงกว่าจุดคุ้มทุน

โค้ดรองรับโหมด:

- `fixed_fractional`: เสี่ยงเป็นเปอร์เซ็นต์ของทุน
- `fixed_stake`: เดิมพันจำนวนเงินคงที่
- `martingale`: แพ้แล้วคูณ 2 จนกว่าจะชนะ ใช้สำหรับการทดลองเท่านั้น

## Martingale

Martingale เป็นโหมดทดลองเท่านั้น:

```text
เริ่ม 100 บาท
แพ้ -> ไม้ถัดไป 200 บาท
แพ้อีก -> 400 บาท
ชนะ -> กลับมา 100 บาท
```

ต้องรายงานเพิ่ม:

- แพ้ติดกันสูงสุด
- ชนะติดกันสูงสุด
- เงินเดิมพันสูงสุด
- จำนวนไม้ที่เปิดจริง
- จุดที่ทุนไม่พอวางไม้ถัดไป
- Maximum drawdown

Martingale ไม่ได้เพิ่มความแม่นยำของโมเดล และ payout 80% ทำให้การคูณ 2 ไม่สามารถชดเชยขาดทุนได้เต็มที่เสมอ จึงต้องแยกผลของโมเดลออกจากผลของระบบจัดการเงิน

## เป้าหมายการพัฒนา

เป้าหมายระยะสั้น:

- ทำให้ผลการทดสอบทำซ้ำได้ด้วยการกำหนด random seed
- ทดสอบข้อมูลอย่างน้อยหลายเดือน
- รายงานผลแยกตามเดือนและช่วงตลาด
- ตรวจสอบ threshold หลายค่าโดยเลือก threshold จาก validation เท่านั้น
- ปรับ spread, payout และ commission ให้ตรงกับโบรกเกอร์จริง
- บันทึกทุกสัญญาณพร้อม timestamp, probability, prediction และผลจริง

เป้าหมายด้านคุณภาพ:

- Accuracy ต้องสูงกว่า break-even rate อย่างสม่ำเสมอ
- ผลลัพธ์ต้องไม่พึ่งพาเดือนใดเดือนหนึ่ง
- Coverage ต้องมากพอสำหรับการใช้งานจริง
- Maximum drawdown ต้องอยู่ในระดับที่ยอมรับได้
- ห้ามใช้ข้อมูลอนาคตในการสร้าง feature หรือเลือก threshold

## ข้อควรระวัง

- Accuracy ประมาณ 70% ไม่ควรถูกตั้งเป็นสมมติฐานล่วงหน้า ต้องพิสูจน์จากข้อมูลที่ไม่เคยใช้ฝึก
- ผลล่าสุดของ pattern signal อยู่ราว 54-55% ซึ่งยังต่ำกว่าจุดคุ้มทุนของ payout 80% ที่ 55.56%
- Money management ช่วยควบคุมการขาดทุน แต่ไม่สามารถเพิ่มความแม่นยำของโมเดลได้
- ผลจากข้อมูล 1 เดือนยังไม่เพียงพอสำหรับสรุปว่าโมเดลใช้งานจริงได้
- XAUUSD มี volatility และ spread เปลี่ยนตามช่วงเวลา
- ผล backtest ไม่ใช่ผลกำไรที่รับประกันในอนาคต
- ควรทดสอบด้วยบัญชีทดลองและข้อมูล out-of-sample ก่อนใช้งานเงินจริง
